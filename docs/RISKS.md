# RISK REGISTER — Phase 0

**Date:** 2026-09-21 · **Scale:** Impact and Likelihood are High / Medium / Low.
Risks are ordered by expected damage, not by phase order.

| # | Risk | Impact | Likelihood | Status of evidence | Mitigation | Owner |
|---|---|---|---|---|---|---|
| 1 | **Arabic / code-switching ASR quality is not good enough**, so every downstream artifact (summaries, decisions, tasks, search, chat) is built on bad text | High | Medium–High | `NOT VERIFIED` — no provider tested on real Arabic audio | Benchmark ≥3 providers on your own recordings in Phase 3 before committing; keep `TranscriptionProvider` swappable; show per-segment confidence; make transcripts human-correctable | You + build team |
| 2 | **No production host decided**, so the always-on worker, public HTTPS URL and persistent storage that the architecture requires do not exist anywhere yet | High | High | `VERIFIED` — this sandbox has no ingress, no persistence, no daemon | Decide the host before Phase 3 (see PLAN §2, decision D1). Verify worker + ingress + storage on that host with a throwaway service before building on it | You |
| 3 | **Legal exposure from recording meetings without proper consent** (two-party consent rules, employee monitoring rules, cross-border recordings) | High | Medium | `NOT VERIFIED` — no legal review done | Written consent + retention policy before any non-team use; per-meeting consent flag; visible recording indicator; retention job in Phase 15; legal review of the jurisdictions you operate in | You |
| 4 | **AI fabricates decisions or action items** that a human then acts on | High | Medium | Design control exists (`docs/01-architecture.md` §5) but is `NOT IMPLEMENTED` | Evidence-linked extraction + deterministic validator that drops unsupported items + suggestion-first status + human acceptance + visible drop counts. Tested against the golden set in Phase 4 | Build team |
| 5 | **Prompt injection via transcript, email or fetched web page** causes an unintended action or data disclosure | High | Medium | Design control exists (`docs/03-security.md` §5) but is `NOT IMPLEMENTED` | Untrusted-data blocks; model never holds credentials or calls providers; Action Gateway + human approval for every external effect; explicit injection test cases in Phases 7 and 13 | Build team |
| 6 | **An email or calendar action fires without real approval, or fires twice** | High | Low–Medium | `NOT IMPLEMENTED` | Action Gateway ships in Phase 9 **before** any integration; approved-payload digest re-checked at execution; unique idempotency keys; provider response id stored as proof; audit log append-only | Build team |
| 7 | **Google restricted-scope verification** (Gmail) delays or blocks the email feature; the review timeline and cost are unknown | Medium–High | Medium | `NOT VERIFIED` — no verification process started | Start the Google Cloud / Azure app registration early; design Phase 11 so read-only and draft-only work without send scope; keep Microsoft 365 as an alternative path | You |
| 8 | **Cost overrun on long or numerous meetings** — a 3-hour meeting re-analyzed several times multiplies token spend | Medium | Medium–High | Partially `VERIFIED` — vendor prices fetched 2026-09-21; token volumes are estimates | `provider_calls` cost recording from Phase 3; per-workspace quotas; cheap model for bulk stages; prompt caching; batch API where latency allows; cost dashboard in Phase 15 | Build team |
| 9 | **pgvector not actually available** on the chosen database, silently pushing search to lexical-only | Medium | Low–Medium | `VERIFIED` absent locally; Neon support is vendor-documented, not tested | Phase 1 must run `CREATE EXTENSION vector` on the real dev database and show the output before any embedding work is scheduled | Build team |
| 10 | **Arabic search returns nothing useful** because Postgres does no Arabic normalization | Medium | High if unmitigated | `VERIFIED` — `similarity('الموقع','الموقـع') = 0.5` for the same word with tatweel | Dedicated normalization function, unit-tested with real Arabic variants, applied to the index only (Phase 6) | Build team |
| 11 | **Storage and egress cost for audio** grows faster than expected, especially playback | Medium | Medium | `NOT VERIFIED` — no provider chosen, no pricing fetched | Store normalized compressed audio for playback, keep originals in cold storage; compare R2 vs S3 egress before choosing; retention policy actually enforced | You + build team |
| 12 | **Neon Free-plan limits** (0.5 GB per project) are hit once embeddings exist, causing failures that look like bugs | Medium | Medium–High | `VERIFIED` — existing project shows a 512 MB branch limit; Neon pricing fetched | Provision a dedicated project on a paid plan before Phase 6; alert on storage growth | You |
| 13 | **Diarization mislabels speakers**, so decisions get attributed to the wrong person | Medium | Medium | `NOT VERIFIED` | Speaker labels are provisional until a human confirms them (Phase 8); ownership fields stay editable; never auto-assign a task to a person from diarization alone | Build team |
| 14 | **Secrets leak** into logs, prompts, or the repository | High | Low | Controls designed, `NOT IMPLEMENTED` | Redaction middleware + a test asserting a known secret never appears in log output (Phase 1); secret scanning in CI; tokens encrypted and referenced by `token_ref`; never returned by any API | Build team |
| 15 | **Cross-tenant data leakage** through a repository method or a retrieval path that forgets the scope filter | High | Low–Medium | `NOT IMPLEMENTED` | `workspace_id` on every row; scope enforced in the repository layer only; negative tests from Phase 1; retrieval re-applies the filter after ranking | Build team |
| 16 | **Ephemeral build environment**: work not committed is lost when the container is reclaimed | Low–Medium | High | `VERIFIED` — sandbox container, reclaimed after inactivity | Commit and push every phase; never keep state only in the container; treat `/tmp` as scratch | Build team |
| 17 | **Scope creep** — 15 phases is a long road, and "one more feature" before the foundation is solid is the classic failure | High | Medium | — | One phase per message; Definition of Done enforced by `docs/12-verification.md`; reject partial phases; keep the phase acceptance table filled | You |
| 18 | **Vendor lock-in / model deprecation** mid-build | Medium | Medium | — | Provider interfaces (ADR 0002); model id and prompt version recorded on every artifact; no vendor SDK outside `packages/providers` | Build team |

## Risks that are currently BLOCKING

- **B1 — Production host undecided** (risk #2). Blocks Phase 3 completion (worker) and Phases 10–11 entirely (OAuth callbacks).
- **B2 — No provider credentials of any kind** (`NOT CONFIGURED`). Blocks any real transcription or analysis work; Phase 1–2 can proceed without them.
- **B3 — Consent/retention policy undecided** (risk #3). Blocks exposing Phase 2 recording to anyone outside the build team.
- **B4 — No real Arabic meeting audio provided** for the golden set. Blocks meaningful Phase 3–4 quality verification.
